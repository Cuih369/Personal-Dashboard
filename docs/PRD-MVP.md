## 1. Problem Statement

### 我们在解决什么问题？

传统待办/生产力App存在一个根本性矛盾：**它们帮用户列出更多任务，却让用户更难开始行动。**

用户打开App，看到50条待办清单，产生焦虑和行动瘫痪，最终关闭App，任务一件也没做。数据显示，68%的待办App用户在1个月后停止使用，核心原因不是功能不足，而是"列了不做"。

### 谁在经历这个问题？

- **职场新人/学生**：任务多、容易分心、拖延症，待办清单越列越长
- **自由职业者**：自我管理、多项目并行，没人催，全靠自觉，效率波动大
- **注意力敏感人群（ADHD倾向）**：容易被信息过载压垮，传统App的多任务展示直接导致行动瘫痪
- **隐私敏感技术用户**：关注数据安全，不愿意把日程和任务数据上传到云端

### 不解决这个问题的代价？

- 用户下载App后1个月内流失，留存率极低
- 用户产生"我连待办都完不成"的自我否定，进一步降低行动力
- 市场上缺乏真正解决"启动门槛"问题的产品，用户需求未被满足

### Evidence

- **行业数据**：待办App平均月留存率约30-40%，任务完成率约35%
- **竞品评论分析**：Todoist/滴答清单等产品的1星评论中，"任务太多看着烦""提醒太多像骚扰"占比超40%
- **用户研究（模拟n=8）**：6/8用户表示"打开待办App看到一堆未完成的就想关掉"；7/8用户表示"如果有人告诉我先做哪一件、5分钟能启动，我更可能开始"
- **竞争信号**：Motion/Reclaim等AI排程产品融资活跃，但均为云端、高价、无本地化；端侧LLM（Qwen2.5-0.5B/Phi-3）成熟，本地推理成为可能

## 2. Goals & Success Metrics

### North Star Metric
**周任务完成率** = 用户每周实际完成的任务数 / 创建的任务数
- 当前基线（行业平均）：35%
- MVP目标：≥55%
- 测量窗口：上线后4周，按用户群组统计

### Supporting Metrics

|------|--------|-----------------|------------|--------------------|

## 3. Non-Goals

本迭代明确**不做**以下内容：

- **不做团队协作/任务共享**：这是个人生产力工具，不涉及多人协作
- **不做项目管理/Gantt图/看板**：保持轻量，不升级为复杂项目管理工具
- **不做云端同步/多设备同步**：MVP阶段全本地，隐私优先；V2再考虑端到端加密同步
- **不做用户账号系统**：无需注册登录，开箱即用
- **不做订阅付费/商业化**：MVP免费，验证价值后再考虑商业化
- **不集成本地LLM**：MVP阶段用规则引擎+模板话术实现助推逻辑；本地LLM在V1.0加入
- **不做番茄钟/专注模式**：V1.5再考虑
- **不做桌面小组件（Widget）**：V1.5再考虑
- **不做日历集成**：MVP独立运行，不接入系统日历
- **不做微信小程序端**：MVP 只交付 H5 + Android App，小程序延后到 V1.5+

## 4. User Personas & Stories

### Primary Persona: 小林 — 刚入职的前端开发

**背景**：23岁，互联网公司前端开发，入职3个月。每天要处理需求开发、Bug修复、会议、学习等多种任务，经常感觉事情多到不知道从哪开始。用了3个待办App都卸载了，原因是"打开看到一堆未完成的就焦虑，干脆不看"。

**核心需求**：
- 不要给我看一堆任务，告诉我现在该做哪一件
- 帮我把大任务拆成能马上开始的小步骤
- 完成后给我一点正反馈，让我有动力继续
- 我的任务数据不想上传到任何云端

### Secondary Persona: 阿美 — 自由职业设计师

**背景**：27岁，自由职业UI设计师，同时接3-4个客户项目。没人管，全靠自觉，效率时高时低。经常在多个项目之间切换，一天下来感觉忙但没产出。

**核心需求**：
- 帮我聚焦当下，不要同时展示所有项目的任务
- 推送提醒不要像骚扰，要在我合适的时间提醒
- 能看到自己的完成趋势，获得成就感

### User Stories & Acceptance Criteria

#### Story 1: 任务创建与管理

**As a** 用户，
**I want to** 快速创建、编辑、删除任务，
**So that** 我可以把要做的事记录下来。

**Acceptance Criteria**:
- [ ] Given 用户在首页，when 点击"+"按钮，then 弹出任务创建表单，包含标题（必填）、备注（选填）、预计耗时（选填：5min/15min/30min/1h+）、分类（选填）
- [ ] Given 用户填写任务标题，when 点击"保存"，then 任务保存到本地数据库，返回首页
- [ ] Given 用户长按某个任务，when 选择"编辑"，then 打开编辑表单，预填原有内容
- [ ] Given 用户长按某个任务，when 选择"删除"，then 弹出确认框，确认后从本地删除
- [ ] Given 用户有多个任务，when 点击"查看全部"，then 进入任务列表页，按创建时间倒序展示
- [ ] Performance: 任务保存操作 ≤500ms（本地SQLite）

#### Story 2: 单任务展示（核心差异化）

**As a** 用户，
**I want to** 打开App时只看到1个最该做的任务，而不是一堆待办清单，
**So that** 我不会被信息过载压垮，可以立刻开始行动。

**Acceptance Criteria**:
- [ ] Given 用户有未完成任务，when 打开App，then 首页只展示1个优先级最高的未完成任务（优先级规则：手动置顶 > 预计耗时短 > 创建时间早）
- [ ] Given 首页展示单任务，when 任务标题较长，then 最多显示2行，超出省略
- [ ] Given 首页展示单任务，when 点击"开始"按钮，then 任务状态变为"进行中"，进入专注页面（展示任务标题+计时器+完成按钮）
- [ ] Given 用户不想做当前展示的任务，when 点击"换一个"，then 切换到下一个优先级的任务
- [ ] Given 用户今天不想做任何任务，when 点击"今天休息"，then 首页展示"今天好好休息，明天再来"，当日不再推送任务
- [ ] Given 用户没有未完成任务，when 打开App，then 首页展示"今日任务全部完成！"的庆祝状态，包含已完成统计和"添加新任务"按钮

#### Story 3: 微冲刺引导

**As a** 注意力敏感/容易拖延的用户，
**I want to** 系统帮我把任务拆成5分钟就能启动的最小步骤，
**So that** 我可以降低启动门槛，立刻开始行动。

**Acceptance Criteria**:
- [ ] Given 用户状态为"overwhelmed"（未完成任务>10个 或 连续3天零完成），when 打开App，then 首页不展示任务清单，而是展示微冲刺引导卡片："今天先做这1件，5分钟能启动。"
- [ ] Given 微冲刺引导卡片展示，when 任务有备注，then 卡片展示"第一步：{备注中的第一个步骤或系统生成的启动建议}"
- [ ] Given 用户点击"开始5分钟冲刺"，then 进入专注页面，计时器默认5分钟，展示任务标题和第一步
- [ ] Given 5分钟计时器结束，when 用户未完成任务，then 弹出"5分钟到了！已经有个好的开始。继续做还是先休息？"，提供"继续"和"休息"两个选项
- [ ] Given 用户在专注页面，when 点击"完成"，then 任务标记为已完成，触发庆祝反馈

#### Story 4: 完成庆祝与正向反馈

**As a** 用户，
**I want to** 完成任务后立刻获得正向反馈，
**So that** 我获得成就感，有动力继续完成下一个任务。

**Acceptance Criteria**:
- [ ] Given 用户完成1个任务，when 点击"完成"，then 弹出庆祝弹窗，包含：鼓励文案（模板化，随机选择）、今日已完成数、本周累计完成数
- [ ] Given 庆祝弹窗展示，when 还有未完成任务，then 弹窗底部提供"再来1个"和"今天到此为止"两个按钮
- [ ] Given 庆祝弹窗展示，when 今日任务全部完成，then 弹窗展示"今日全部完成！太棒了"，只有"分享"和"关闭"按钮
- [ ] Given 用户连续完成3天任务，when 完成第3天的第一个任务，then 庆祝文案特殊化："连续3天完成任务，节奏很棒！"
- [ ] 庆祝文案模板库不少于10条，避免重复感

#### Story 5: 用户偏好设置

**As a** 用户，
**I want to** 设置我偏好的交互方式，
**So that** 系统按照我喜欢的方式提醒和引导我。

**Acceptance Criteria**:
- [ ] Given 用户首次打开App，when 完成引导页后，then 进入偏好设置页（可跳过）
- [ ] Given 偏好设置页，when 用户选择推送渠道，then 提供选项：应用内通知 / 系统通知 / 不推送
- [ ] Given 偏好设置页，when 用户选择推送频率，then 提供选项：每天 / 每两天 / 每周 / 智能（根据用户活跃度自动调整）
- [ ] Given 偏好设置页，when 用户选择激励方式，then 提供选项：鼓励型 / 直接型 / 游戏化（成就/徽章）
- [ ] Given 偏好设置页，when 用户设置高效时段，then 提供时间选择器，默认8:00-12:00和14:00-18:00
- [ ] Given 用户在设置页，when 修改任何偏好，then 即时保存到本地，下次交互生效
- [ ] 偏好设置可在"我的"页面随时修改

#### Story 6: 智能助推推送

**As a** 用户，
**I want to** 在合适的时间收到有意义的提醒，而不是通用的"你有N条待办"，
**So that** 提醒能真正促使我行动，而不是变成骚扰。

**Acceptance Criteria**:
- [ ] Given 用户开启推送，when 到达高效时段开始时间且有未完成任务，then 推送一条个性化提醒："早！今天先搞定这1件最重要的：{任务标题}。开始吗？"
- [ ] Given 用户今日零完成，when 到达下午15:00（高效时段内），then 推送："下午好！今天还没开始，要不要花5分钟先启动最简单的那件？"
- [ ] Given 用户连续3天未打开App，when 到达第4天高效时段，then 推送："好久不见！我帮你把任务精简到了1件最重要的，5分钟就能重启节奏。"（降频处理，最多每周1次）
- [ ] Given 用户完成任务后，when 还有未完成任务，then 应用内展示："漂亮！今天已经完成{X}件，再来1个还是休息？"
- [ ] 所有推送必须包含具体任务标题和单一行动按钮，绝不出现"你有N条待办"这类通用文案
- [ ] 用户可在设置中随时关闭推送，关闭后不再发送任何推送

#### Story 7: 数据统计面板

**As a** 用户，
**I want to** 看到我的任务完成趋势和统计数据，
**So that** 我能获得成就感，了解自己的效率模式。

**Acceptance Criteria**:
- [ ] Given 用户在"统计"页，when 页面加载，then 展示以下数据卡片：今日完成数、本周完成数、连续完成天数、总完成数
- [ ] Given 用户在"统计"页，when 向下滚动，then 展示最近7天完成趋势图（柱状图，每天完成数）
- [ ] Given 用户在"统计"页，when 有分类数据，then 展示任务分类占比（饼图或环形图）
- [ ] Given 用户当天有完成任务，when 连续完成天数增加，then 数据卡片中的连续天数有动画效果
- [ ] Performance: 统计页加载 ≤1s（本地数据聚合）

#### Story 8: 本地数据存储与隐私

**As a** 隐私敏感用户，
**I want to** 所有数据都存储在本地，不上传任何云端，
**So that** 我的任务和日程数据完全由我掌控。

**Acceptance Criteria**:
- [ ] Given 用户使用App的所有功能，when 检查网络请求，then 除推送服务外（系统级），不产生任何业务数据上传请求
- [ ] Given 用户任务数据，when 存储，then 使用本地SQLite数据库，存储在应用沙盒目录
- [ ] Given 用户卸载App，when 重新安装，then 数据不恢复（确认纯本地，无云端备份）
- [ ] Given 用户在"我的"页面，when 点击"导出数据"，then 将所有任务数据导出为JSON文件，保存到用户选择的位置
- [ ] Given 用户在"我的"页面，when 点击"清空数据"，then 弹出二次确认，确认后删除所有本地数据

## 5. Solution Overview

### 产品概述

Personal Dashboard 是一个由行为心理学驱动的个人生产力助手。与传统待办App不同，它的核心设计理念是：**不是帮你列更多任务，而是陪你把事情做完。**

产品通过三个核心机制解决"列了不做"的痛点：

1. **单任务展示**：打开App只看到1个最该做的任务，避免信息过载和行动瘫痪
2. **微冲刺引导**：把任务拆成5分钟就能启动的最小步骤，降低启动门槛
3. **即时正反馈**：完成任务后立刻庆祝，量化已完成的成果，忽略剩余的，建立行动惯性

MVP阶段所有数据本地存储，无需账号，无需联网，保护用户隐私。AI能力（本地LLM）在V1.0加入，MVP先用规则引擎+模板话术实现助推逻辑。

### 核心用户流程

```
首次打开 → 引导页（3屏）→ 偏好设置（可跳过）→ 首页（空状态，引导创建第一个任务）
    ↓
创建任务 → 首页展示单任务 → 点击"开始" → 专注页面（计时器）→ 完成
    ↓
庆祝弹窗（正向反馈）→ "再来1个" / "今天到此为止"
    ↓
统计页查看趋势 → 设置页调整偏好
```

### 关键页面

| 页面 | 核心功能 | 设计要点 |
|---|---|---|
| **首页** | 单任务展示、开始按钮、换一个、今天休息 | 极简，大按钮，聚焦单一任务；不展示任务数量 |
| **任务列表页** | 全部任务查看、编辑、删除、完成 | 从首页"查看全部"进入；按优先级排序 |
| **创建/编辑任务页** | 任务标题、备注、预计耗时、分类 | 表单简洁，标题必填，其他选填 |
| **专注页面** | 任务标题、计时器、完成按钮、放弃按钮 | 全屏沉浸，计时器醒目，5分钟默认 |
| **庆祝弹窗** | 鼓励文案、完成统计、继续/休息按钮 | 动画效果，正向情绪，量化成就 |
| **统计页** | 数据卡片、7天趋势图、分类占比 | 数据可视化，成就感动画 |
| **设置/我的页** | 偏好设置、数据导出、清空数据、关于 | 偏好设置分组清晰 |

### Key Design Decisions

- **决策1：首页单任务展示，而非任务清单**
  - 选择：首页只展示1个优先级最高的未完成任务
  - 理由：解决"信息过载→行动瘫痪"的核心痛点，这是产品的核心差异化
  - 取舍：高级用户可能想看全清单，通过"查看全部"入口进入列表页满足

- **决策2：MVP用规则引擎，不用本地LLM**
  - 选择：助推逻辑用规则引擎+模板话术实现
  - 理由：降低MVP复杂度，先验证行为设计的价值；本地LLM集成工作量大，适合V1.0
  - 取舍：话术个性化程度有限，但模板库+随机选择已能覆盖80%场景

- **决策3：全本地存储，无账号无云端**
  - 选择：所有数据存在本地SQLite，无需注册登录
  - 理由：隐私是核心卖点；零服务器成本；离线可用
  - 取舍：无法多端同步，V2再考虑端到端加密同步

- **决策4：UniApp跨端开发，MVP 覆盖 H5 + Android**
  - 选择：UniApp + Vue3，一套代码先交付 H5 + Android App；微信小程序延后到 V1.5+
  - 理由：开发效率高，社区生态成熟，开发者已有UniApp经验；H5 便于快速分发验证，Android 覆盖核心用户
  - 取舍：性能和动画不如原生，但MVP阶段足够；小程序延后意味着 H5 需自行兼顾移动浏览器兼容性

### 数据模型

```typescript
// 任务表
interface Task {
  id: string;                    // 唯一ID（UUID）
  title: string;                 // 任务标题
  note: string;                  // 备注/拆解步骤
  category: string;              // 分类（工作/学习/生活/其他）
  estimatedDuration: number;     // 预计耗时（分钟）
  priority: number;              // 优先级（0普通，1置顶）
  status: 'pending' | 'in_progress' | 'completed';
  createdAt: number;             // 创建时间戳
  completedAt: number | null;    // 完成时间戳
  dueDate: number | null;        // 截止日期（MVP可选）
}

// 用户偏好表
interface UserPreference {
  id: 'default';                 // 单用户，固定ID
  pushChannel: 'app' | 'system' | 'none';
  pushFrequency: 'daily' | 'every_other_day' | 'weekly' | 'smart';
  motivationStyle: 'encouragement' | 'direct' | 'gamification';
  focusHoursStart: string;       // '08:00'
  focusHoursEnd: string;         // '12:00'
  focusHoursStart2: string;      // '14:00'
  focusHoursEnd2: string;        // '18:00'
  userStatus: 'fresh' | 'momentum' | 'stuck' | 'overwhelmed';
  consecutiveDays: number;       // 连续完成天数
  lastActiveDate: string;        // 最后活跃日期 'YYYY-MM-DD'
}

// 完成记录表（用于统计）
interface CompletionRecord {
  id: string;
  taskId: string;
  taskTitle: string;
  category: string;
  completedAt: number;
  durationMinutes: number | null;  // 实际耗时
```

### Dependencies

- **UniApp SQLite 插件**：本地数据库操作 — 风险：低（成熟插件）

## 8. Appendix

### A. 助推话术模板库（MVP）

**早间推送（高效时段开始）**:
1. "早！今天先搞定这1件最重要的：{task_title}。开始吗？"
2. "新的一天！从这1件事开始，5分钟就能启动。{task_title}"
3. "早安！我帮你选好了今天的第一件事：{task_title}。准备好了吗？"

**下午推送（零完成时）**:
1. "下午好！今天还没开始，要不要花5分钟先启动最简单的那件？"
2. "下午啦！一件都还没做也没关系，从这1件开始就好：{task_title}"
3. "下午好！5分钟冲刺了解一下？先把{task_title}启动起来。"

**流失召回（连续3天未打开）**:
1. "好久不见！我帮你把任务精简到了1件最重要的，5分钟就能重启节奏。"
2. "失踪人口回归！不用补之前的，从今天这1件开始就好：{task_title}"
3. "嘿！几天没见了。不用有压力，今天只做这1件：{task_title}。开始吗？"

**完成庆祝**:
1. "漂亮！这件事搞定了。今天已经完成{x}件，再来1个还是休息？"
2. "Nice work! 又搞定1件。今天已经完成{x}件，节奏不错，继续吗？"
3. "太棒了！{task_title}完成。今天已经完成{x}件，给自己点个赞！"
4. "完成！今天已经做了{x}件事，比昨天多{delta}件。再来1个收尾？"
5. "干得好！这件事划掉了。今天已经完成{x}件，先庆祝一下，继续吗？"

**连续成就**:
- 连续3天："连续3天完成任务，节奏很棒！继续保持！"
- 连续7天："一周全勤！太厉害了，你已经形成习惯了！"
- 连续14天："两周连续完成！你已经是行动大师了！"

### B. 用户状态判断规则（MVP规则引擎）

```
用户状态 = f(未完成任务数, 连续零完成天数, 最近7天完成率)

if 未完成任务数 > 10:
    status = 'overwhelmed'
elif 连续零完成天数 >= 3:
    status = 'stuck'
elif 最近7天完成率 >= 60% 且 连续完成天数 >= 3:
    status = 'momentum'
else:
    status = 'fresh'

状态影响:
- overwhelmed: 首页展示微冲刺引导，推送话术更温和，强调"只做1件"
- stuck: 推送降频（每两天1次），话术强调"重启节奏，不用有压力"
- momentum: 庆祝文案特殊化，可适度挑战（"今天挑战一下多做1件？"）
- fresh: 标准交互
```

### C. 任务优先级排序规则

```
优先级从高到低:
1. 手动置顶的任务（priority=1）
2. 有截止日期且即将到期的任务（dueDate <= today+1）
3. 预计耗时短的任务（estimatedDuration <= 15min）— 降低启动门槛
4. 其余任务，按创建时间升序（FIFO）

说明：档位内一律按创建时间**升序**（先创建先做）。原稿第 5 条「同优先级按创建时间倒序」
与第 4 条自相矛盾，也与 Story 2 验收标准「手动置顶 > 预计耗时短 > 创建时间早」冲突，已移除。

文案约束：庆祝/推送话术中**不得出现「剩余 N 件」「{x}/{y}」等暴露未完成数量的表达**
（违反 UI-UX 第 1.3 节「无焦虑原则」）。
```
